# 应用中心人员月度考核功能 - 需求规格 (spec.md)

## 1. 问题与用户

**问题**：天地信息网络研究院CRM系统目前没有应用中心人员的考核模块。管理者无法设置每个人的年度新签合同额指标、无法自动分解为月度指标、无法自动计算绩效工资、无法导出月度完成率。

**用户角色**：
- **主任/院长（应用中心管理者）**：设置考核指标、查看全员完成率、导出考核数据
- **主任**：身兼多职且包含"销售"角色时，按销售考核
- **所有应用中心人员**：查看自己的考核详情与工资构成

## 2. 业务规则与核心公式

### 2.1 考核身份判定（优先级从高到低）
- **销售身份**：`users.role == '销售'` **或** 身兼多职且包含"销售"（按 `users.is_sales_override=1` 强制销售身份）
- **非销售身份**：应用中心内不销售的人员（主任、售前、技术研发、采购……），含主任非销售身份的情况
- **身兼多职有销售的按销售人员考核**：主任如果既管行政又做销售，只要其名下有合同 owner_id 匹配（或开启 is_sales_override），即按销售公式计算绩效工资

### 2.2 指标体系
- **年度新签合同额指标**（`annual_target_amount`，单位：元，按年设置）
- **月度新签合同指标**（`monthly_target_amount`，单位：元）= 年度指标 / 12（自动计算，允许手工微调每个月的分解值，例如旺季提高、淡季降低）
- **实际新签合同额**：`contracts` 表中 `owner_id=当前用户` 且 `sign_date` 在评估月份内的合同 `total_amt` 之和（单位：元）
- **月度累计完成率** = 该月 `实际新签合同额` / `月度指标`。上限 **150%**（封顶避免异常放大绩效），若 `月度指标 <= 0` 则视为未设置指标，完成率记为 0（不计算绩效，避免除以 0）
- **销售月平均完成率**：当月所有销售身份人员的累计完成率算术平均值（剔除月度指标<=0的销售）

### 2.3 工资构成
**工资 = 基本工资 + 绩效工资**

| 人员身份 | 绩效工资公式 |
|---|---|
| 销售 | `基础绩效工资 × min(月度累计完成率, 150%)` |
| 非销售（含主任非销售身份） | `基础绩效工资 × min(销售月平均完成率, 150%)` |

- **基本工资**（`basic_salary`）：固定发放，单位元
- **基础绩效工资**（`base_performance`）：满额绩效基数，单位元
- 金额显示**精确到分**（两位小数），计算时不丢精度

## 3. 功能需求（FR）

### FR1 指标配置页（主任/院长可操作）
- 在 `users` 表上给每个在职用户设置：`basic_salary`（基本工资）、`base_performance`（基础绩效工资）、`annual_target_amount`（年度新签合同额指标）、`is_sales_override`（是否强制按销售考核，1/0）
- "年度指标"自动分解为 12 个"月度指标"（默认 ÷12），但允许主任对每个月独立手工修改（例如1月旺季设高，2月设低）
- 修改月度分解值时不影响原始年度指标的存储（即年度指标 + 月度覆盖值两套字段）

### FR2 月度考核总览页
- 按"年份"和"月份"筛选（默认当前年当前月）
- 表格展示应用中心每位在职人员的考核数据：
  姓名、角色、身份判定（销售/非销售）、年度指标、当月指标、当月实际新签合同额、当月累计完成率、基本工资、基础绩效工资、绩效工资、当月实发工资
- 高亮：完成率>=100% 绿色；<60% 红色；60%-99% 黄色
- 汇总行：全员合计 实际新签、完成率均值、实发工资总额

### FR3 月度完成率导出
- 主任/院长可点击"导出月度考核表"，下载当月考核 Excel 或 CSV（.xlsx 优先，openpyxl 已安装）
- 导出列与 FR2 表格列一致，含表头中文
- 文件名示例：`2026年8月-应用中心月度考核表.xlsx`

### FR4 我的考核（每人可见）
- 当前登录用户可见"自己的本月考核详情"：月度指标、本月已签合同明细列表（合同号、名称、金额、签约日）、完成率进度条、工资构成明细

### FR5 权限与可见性
- **主任/院长**：可配置指标、查看全员考核、导出
- **普通用户**：仅可查看自己的考核（FR4）
- 所有考核页面对"应用中心"部门以外的用户不可见（路由守卫拦截）

## 4. 非功能需求（NFR）

- **性能**：考核页打开 < 2s（一次 SQL 聚合查询即可出所有数据）
- **兼容性**：合同表已有 owner_id/username 匹配，不依赖任何新的外部系统
- **精度**：所有金额保留两位小数，百分比保留两位小数（如 87.35%）
- **数据安全**：任何考核修改（指标配置）记录 operation_logs 操作日志
- **数据完整性**：删除/作废的合同（contracts.status != '执行中'？需确认字段）不算入实际新签合同额。若合同表无作废字段，则所有 `owner_id` 匹配的合同都计入（因为合同归档一般仍代表业绩），**合同签订日期在月份内即计入**，不按回款日期

## 5. 约束与假设

- **数据来源**：`contracts` 表 `owner_id` 存的是 username（已在前一轮验证，历史数据全部匹配 username）。这是考核归属的唯一依据
- **已删除/作废合同**：若 contracts 表没有作废状态字段，暂时不区分；如有作废字段，作废合同不计入
- **身兼多职**：用户只有一个 role 字段，额外新增 `is_sales_override` 标志支持"身兼多职有销售"场景
- **月度分解默认值**：年度指标 ÷12，保留两位小数；用户可手工覆盖每个月的值，但 12 个月之和不得超过年度指标 ±10元（允许四舍五入误差）
- **当月为未结束月**：当月实际新签合同额按签约日期至今（today）统计，会随新签合同实时自动增加

## 6. 非目标（不做）

- 不做历史月份的"回算/锁月"：本月任何时候查看/导出都按当前合同数据实时计算
- 不做工资发放/银行代发接口：考核页面只展示应发工资，不与实际工资发放联动
- 不做季度/年度维度的考核：仅月度维度
- 不做跨部门考核：只应用中心（department='应用中心'）人员。若 department 为空则暂时按所有在职人员计算（兼容现有历史 users 数据 department 为空的情况）

## 7. 验收标准（AC）

每个 AC 类型为 `rule` 或 `rubric`。

| # | 类型 | 标准 |
|---|---|---|
| AC1 | rule | 数据库 `users` 表新增 `basic_salary, base_performance, annual_target_amount, is_sales_override` 字段并均有默认值（金额0，标志0） |
| AC2 | rule | 数据库新增 `monthly_targets` 表（存储每个用户每年每月的月度指标覆盖值）和 `monthly_assessment_logs` 表（记录指标修改） |
| AC3 | rule | 后端接口 `GET /api/appraisal/monthly?year=2026&month=8` 返回每个应用中心在职用户的考核数据，包含：年度指标、月度指标（含覆盖值）、当月实际新签合同额、累计完成率（封顶150%，<=0记0）、基本工资、基础绩效工资、绩效工资（按身份公式正确区分销售/非销售）、实发工资、销售月平均完成率。金额均两位小数，百分比两位小数。 |
| AC4 | rule | 身份判定测试：role='销售' → 销售身份；role='主任' 且 is_sales_override=1 → 销售身份；role='售前' 且 is_sales_override=0 → 非销售身份 |
| AC5 | rule | 指标配置接口 `POST /api/appraisal/config` 能保存基本工资、基础绩效、年度指标、is_sales_override、每月覆盖值，并记录 operation_logs |
| AC6 | rule | `GET /api/appraisal/export?year=2026&month=8` 返回 HTTP attachment 的 .xlsx 文件，列与考核表一致，中文表头，文件名含年月 |
| AC7 | rule | `GET /api/appraisal/mine?year=2026&month=8` 返回当前用户自己的考核详情 + 本月已签合同明细列表 |
| AC8 | rule | 权限：主任/院长可访问 /config /monthly /export；普通用户仅可访问 /mine；非应用中心用户全部拒绝（403） |
| AC9 | rule | 前端新增路由 `/appraisal`，Layout 菜单新增"月度考核"入口，权限与路由守卫一致 |
| AC10 | rubric | 前端考核总览页 UI 质量（0-2）：表格展示所有 AC3 字段，完成率带色阶高亮，汇总行正确，筛选年份/月份正常切换 → 2=完美，1=字段全但样式/色阶有瑕疵，0=字段缺失 |
| AC11 | rubric | 前端指标配置表单质量（0-2）：可输入4项指标 + 12个月覆盖值，校验 12月之和约等于年度指标（±10元内）→ 2=校验通过且交互流畅，1=有校验但体验粗糙，0=无校验或字段缺失 |
| AC12 | rule | 端到端：创建一条测试合同 assign 给某销售 → 考核页该销售当月"实际新签合同额"自动增加 → 完成率和绩效工资正确变化 → 非销售人员的绩效工资按所有销售平均完成率变化 |
