# 客户集中存储 + 3D画像（全生命周期轨迹）

## Context（背景）

当前客户管理存在两个差距：

1. **集中存储不完整**：`customers` 表已有 contact_name/email/industry/region 等字段，后端 POST/PUT 也已支持这些字段，但前端添加/编辑表单（[Customers.vue:52-77](file:///c:/Program%20Files/python/crm/frontend/src/views/Customers.vue)）只暴露了 name/phone/company/level/source/owner_id，导致联系人姓名、邮箱、行业、地区无法录入。

2. **无全生命周期视图**：现有"跟进"弹窗只展示 follow_logs，未聚合商机、合同、拜访记录，无法呈现客户"3D画像"。

目标：补全表单字段实现集中存储；新增客户画像视图，聚合跟进/商机/合同/拜访四类事件，以统一时间轴完整呈现客户全生命周期轨迹。

## 数据关联关系（实测）

- `business.cust_id` → customers.id
- `contracts.party_a` → customers.company（文本匹配甲方公司名）；`contracts.b_id` → business.id（经商机间接关联）
- `visits.cust_id` → customers.id
- `follow_logs` (ref_type='customer', ref_id) → customers.id
- ⚠️ `users` 表有 status 列，business/contracts/visits 也有 status 列 → JOIN users 时必须用表别名限定（c.status/b.status/ct.status/v.status），否则报 ambiguous column

## 实现方案

### 一、后端：新增画像聚合端点

**文件**：[backend/routes/customers.py](file:///c:/Program%20Files/python/crm/backend/routes/customers.py)（在 `register_routes` 前新增端点，约 80 行）

新增 `GET /api/customers/<int:cust_id>/profile`，`@token_required` 鉴权，返回：

```python
{
  'code': 200, 'data': {
    'customer': {...},      # 基本信息 + owner_name
    'follow_logs': [...],   # ref_type='customer', ref_id=cust_id，按 created_at DESC
    'business': [...],      # cust_id=cust_id，按 created_at DESC
    'contracts': [...],     # party_a=company OR b_id IN (该客户的商机)，按 sign_date DESC
    'visits': [...],        # cust_id=cust_id，按 plan_date DESC
    'stats': { business_count, contract_count, contract_total_amt(元), visit_count, follow_count }
  }
}
```

关键要点：
- **权限**：先查客户做 404 校验，主任/院长可查所有，其他仅查 `owner_id = username`（403）
- **5 条聚合查询**全部用表别名限定列名（customers 别名 `c`、business `b`、contracts `ct`、visits `v`、follow_logs `fl`、users `u`），避免 status 歧义
- **合同双重关联去重**：`SELECT DISTINCT ct.* ... WHERE ct.party_a = ? OR ct.b_id IN (SELECT id FROM business WHERE cust_id = ?)`；company 为空时加 `AND ct.party_a != ''` 防御
- **统计**在 Python 端对已查结果求和，避免额外 SQL；total_amt 单位为元，前端再除 10000
- 后端 POST/PUT 已支持全部字段，**无需修改**

### 二、前端：增强表单 + 画像 Drawer

**文件**：[frontend/src/views/Customers.vue](file:///c:/Program%20Files/python/crm/frontend/src/views/Customers.vue)

**改动 A — 表单补全 4 字段**（在"公司名称"后插入）：联系人姓名(contact_name)、邮箱(email)、行业(industry，下拉可输入)、地区(region)。扩展 `customerForm` reactive 对象加入这 4 字段。`editCustomer` 用 `Object.assign(customerForm, row)` 自动回填（GET 已返回 c.*）。

**改动 B — 操作列新增"画像"按钮**：在"跟进"后插入 `<el-button size="small" type="success" @click="showProfile(scope.row)">画像</el-button>`，操作列 min-width 调到 260。

**改动 C — 新增 el-drawer 画像视图**（首次引入 el-drawer，Element Plus 原生支持）：
- **基本信息卡片**：el-descriptions 两列展示 12 个字段（联系人/公司/电话/联系人姓名/邮箱/行业/地区/等级/来源/负责人/创建时间/最后跟进）
- **统计概览**：4 个 mini 卡片（商机数/合同总额万/拜访数/跟进数），金额用 formatAmount（元÷10000，参考 [Dashboard.vue:181](file:///c:/Program%20Files/python/crm/frontend/src/views/Dashboard.vue)）
- **全生命周期时间轴**：el-timeline，4 类事件合并倒序

**改动 D — 时间轴合并 computed `timelineEvents`**：
- 四数据源各映射为 `{ time, typeLabel, color, hollow, title, desc, meta }`
- 时间字段：follow_logs 用 `log_time||created_at`；business 用 `created_at`；contracts 用 `sign_date`；visits 用 `actual_date||plan_date`+时间
- 颜色区分：跟进=primary、商机=warning、合同=success、拜访按状态 success(完成)/info(取消)/primary(计划)，未完成用 hollow
- 排序：`time.localeCompare` 倒序（均为 YYYY-MM-DD[ HH:MM:SS] 格式，字典序与时间序一致）

**改动 E — 样式**：profile-container、stats-row(grid 4列)、stat-mini、event-card 等。
