# 合同关联客户与商机 — 实现计划

## Context（背景与目标）

客户3D画像的"全生命周期轨迹"中，商机、合同之间没有关系，合同和客户也没有关系。根因调查：

- `contracts` 表**无 `cust_id` 字段**，合同无法直接关联客户
- `contracts.b_id`（关联商机）形同虚设：154 条合同中 149 条 NULL、5 条空字符串，**0 条真正关联商机**
- 前端合同表单**无"关联商机"选择器UI**，`b_id` 永远为空
- `update_contract` 的 UPDATE 语句**完全没有 b_id**（编辑时无法补关联）
- 画像接口用 `party_a=公司名` 宽泛关联，导致同公司（38所有43个联系人）所有合同全塞进来，与客户/商机无关

**目标**：建立"客户→商机→合同"三级关联链，让画像中的合同精确归属客户、明确关联商机。

**用户确认的决策**：
- 历史无 cust_id 的老合同：模糊兜底 + 标注"待关联"，引导编辑补关联（一旦补关联即从其他同公司客户画像消失）
- 新建合同"关联客户"必填，"关联商机"可选

## 实现步骤

### 1. 数据库迁移 — `backend/extensions.py`
- 新增 `_init_contracts_table(cursor)`：幂等 `ALTER TABLE contracts ADD COLUMN cust_id INTEGER`（try/except 吞掉 duplicate column，参考既有 `_init_business_table` L91-L130 风格）
- 在 `_init_tables`（L48-L54）中注册调用，置于 `_init_business_table` 之后
- 迁移由 `get_db()` 首次连接自动触发，无需单独脚本；新列默认 NULL 表示"待关联"
- 不做批量回填（75/80 的 party_a 无客户匹配，3/80 多匹配有歧义）

### 2. 后端合同 CRUD — `backend/routes/contracts.py`
- **`get_contracts`（L14-L75）**：4 个 SELECT 分支统一 LEFT JOIN customers + business，返回 `customer_name`、`business_title`
- **`get_contract`（L97-L107）**：单条查询同样 JOIN 返回关联名
- **`create_contract`（L110-L154）**：
  - 开头加 b_id→cust_id 一致性兜底（若传 b_id，用 `business.cust_id` 覆盖 cust_id，防数据撕裂）
  - INSERT 列清单加 `cust_id`，参数加 cust_id
  - 规范化 `b_id = b_id or None`（避免空字符串）
- **`update_contract`（L157-L191）**【核心 bug 修复】：
  - 同样加 b_id→cust_id 兜底 + b_id 规范化
  - UPDATE SET 增加 `cust_id=?` 和 `b_id=?`（当前完全缺失）
- 导入接口（L350+）不变，导入合同 cust_id/b_id 为 NULL，走模糊兜底

### 3. 画像接口重构 — `backend/routes/customers.py`
- **`get_customer_profile` 合同查询块（L227-L247）整体替换**：
  - 主关联：`cust_id = 当前客户`（精确）
  - 模糊兜底：`cust_id IS NULL AND party_a = 公司名`（仅未被认领的历史合同）
  - 新增 `linkage` 字段：`precise`（精确）/ `fuzzy`（模糊待关联）/ `other`
  - 去掉 `b_id IN (SELECT id FROM business WHERE cust_id=?)` 子句（全库0命中且制造混淆）
  - LEFT JOIN business 带 `business_title`，LEFT JOIN customers 带 `customer_name`
- **`delete_customer`（L118，补充）**：增加 `UPDATE contracts SET cust_id=NULL WHERE cust_id=?`，避免悬空外键（与现有 `UPDATE business SET cust_id=NULL` 并列）

### 4. 前端合同表单 — `frontend/src/views/Contracts.vue`
- **`contractForm`（L521-L538）**：增加 `cust_id: null`、`b_id: null`（L1051 已有 `b_id:''` 改为 null 并补 cust_id）
- **新增数据源与联动**（script setup 顶部）：
  - `customers`、`businessList` ref
  - `filteredBusiness` computed：按 `contractForm.cust_id` 过滤商机
  - `fetchCustomers(keyword)`：调 `api.get('/customers', { keyword })`（注意：第二参直接是 params 对象，**不要**照抄 Business.vue 的 `{params:{keyword}}` 错误写法）
  - `fetchBusinessList()`：调 `api.get('/business', { status: 'active' })`
  - `onCustomerChange(custId)`：选客户后自动带出 party_a（仅空时）+ 清空不匹配的 b_id
- **表单 UI**（模板 L197 前）新增一行两个选择器：
  - "关联客户"：el-select filterable remote，必填（rules 加 required 校验）
  - "关联商机"：el-select filterable，`:disabled="!contractForm.cust_id"`，options 用 filteredBusiness
- **`addContract`（L825）/ `watch(showAddModal)`（L1023）**：重置含 cust_id/b_id=null；弹窗打开懒加载客户/商机列表
- **`editContract`（L783）**：回填 `cust_id = row.cust_id || null`、`b_id = row.b_id || null`；确保列表已加载
- **`allColumns`（L479）**：增加 `customer_name`（关联客户）、`business_title`（关联商机）列

### 5. 前端画像时间轴 — `frontend/src/views/Customers.vue`
- **`timelineEvents` 合同分支（约 L570-L583）改造**：
  - 按 `c.linkage` 区分：`fuzzy` → typeLabel="合同(待关联)"、color="info"、hollow=true
  - meta 增加 `customer_name`（客户）、`business_title`（商机）展示，fuzzy 时加"⚠ 按公司名模糊关联，请编辑合同精确指定客户"
  - 完整呈现"客户→商机→合同"链路
- 商机事件分支无需改动

## 数据一致性保障
- b_id→cust_id 后端兜底：杜绝"商机属客户A、合同挂客户B"撕裂
- b_id 规范化为 None：避免历史空字符串再现
- 模糊关联退出机制：老合同被编辑写入 cust_id 后，`cust_id IS NULL` 条件不再命中，自动从其他同公司客户画像消失
- 客户删除同步清理 contracts.cust_id

---

## 验证方法
1. **迁移验证**：重启后端，查 `PRAGMA table_info(contracts)` 确认 cust_id 列存在；老数据 cust_id 为 NULL
2. **API 验证**：用 `scripts/verify_profile_api.py` 调画像接口，确认：
   - 客户73 合同返回 `linkage` 字段（fuzzy，因历史无 cust_id）
   - 合同带 `business_title`（b_id 为空时为 null）
3. **新建合同验证**：合同表单选客户后 party_a 自动带出、商机下拉按客户筛选；保存后查库 cust_id 已写入
4. **编辑老合同验证**：编辑一条38所老合同选客户73，保存后客户73画像该合同 linkage 变 precise；其他38所客户画像该合同消失
5. **画像时间轴验证**：fuzzy 合同显示"待关联"灰色空心节点 + 提示；精确合同显示绿色实心 + 客户名/商机名
6. **必填校验**：新建合同不选客户时表单报错阻止提交
