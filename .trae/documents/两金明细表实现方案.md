# 两金明细表（季度应收账款 + 合同资产）

## Context

每季度最后一天财务需要向集团上报「两金明细表」（应收账款 + 合同资产），目前系统内已有合同/验收/回款数据，但缺少：
1. 客户性质分类字段（6 类：国企/政府/民企/其它事业单位/集团内/子集团内）
2. 按季度末快照的自动统计
3. 风险评级与更新回款计划的人工填报留痕
4. 标准格式 Excel 导出

## 业务口径（已确认）

- **客户性质 6 类**：国内地方客户-地方国企 / 国内地方客户-政府 / 国内地方客户-民企 / 国内地方客户-其它事业单位 / 集团内 / 子集团内；空值默认归"其它事业单位"
- **应收账款** = 含税收入（累计验收额 + 总税额） − 已回款金额
- **合同资产** = 合同总额 − 含税收入（即待验收合同额）
- **形成应收账款日期** = 该合同最早一条验收记录的 acceptance_date（首次确认收入日）；无验收记录 → 不纳入报表
- **账龄分档**（按快照日）：1 年内 / 1-2 年 / 2-3 年 / 3 年以上
- **回款风险自动评级**：1 年内=低 / 1-2 年=中 / ≥2 年=高，人工可改
- **生成方式**：scheduler 在 3/31、6/30、9/30、12/31 自动落库 + 页面可随时手动重新生成 + 导出 Excel

## 存储设计（新建 2 张表）

不污染 contracts 主档，人工填报独立留痕：

```sql
CREATE TABLE receivable_snapshots (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  quarter VARCHAR(8) NOT NULL,           -- '2026Q3'
  snapshot_date VARCHAR(10) NOT NULL,    -- '2026-09-30'
  contract_id BIGINT NOT NULL,
  cust_id BIGINT NOT NULL,
  customer_name MEDIUMTEXT,              -- 冗余便于历史回放
  customer_nature MEDIUMTEXT,            -- 冗余快照时点的客户性质
  receivable DOUBLE,                     -- 应收账款
  contract_asset DOUBLE,                 -- 合同资产
  ar_date VARCHAR(19),                   -- 形成应收账款日期
  aging_bucket VARCHAR(16),              -- 1年内/1-2年/2-3年/3年以上
  auto_risk VARCHAR(4),                  -- 低/中/高
  created_at VARCHAR(19),
  UNIQUE KEY uk_quarter_contract (quarter, contract_id)
);
CREATE TABLE receivable_overrides (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  quarter VARCHAR(8) NOT NULL,
  contract_id BIGINT NOT NULL,
  cust_risk VARCHAR(4),                  -- 客户风险（人工）
  payback_risk VARCHAR(4),               -- 回款风险（人工覆盖）
  payback_plan MEDIUMTEXT,               -- JSON [{node, amt, date}]
  updated_by MEDIUMTEXT,
  updated_at VARCHAR(19),
  UNIQUE KEY uk_quarter_contract (quarter, contract_id)
);
```

建表语句加到 `extensions.ensure_tables` 的表清单（参考 extensions.py 现有 76 张表清单，第 73 行附近），并保持 AUTO_INCREMENT。

## 后端实现

### 1. 新增 `backend/routes/receivables.py`

端点：
- `GET /api/receivables?quarter=2026Q3&nature=...` — 查询快照（默认返回最新季度），LEFT JOIN overrides 合并人工填报
- `POST /api/receivables/snapshot` — 手动触发当前季度快照（财务角色）
- `PUT /api/receivables/override/<contract_id>` — 保存人工填报（quarter 入参）
- `GET /api/receivables/export?quarter=...` — 导出 Excel，复用 `reports.py` 现有 openpyxl + send_file 模式（行 597 附近 `/api/reports/export`）

核心装配 SQL（单条完成，避免 N+1）：

```sql
SELECT c.id, c.contract_name, c.contract_no, c.total_amt, c.paid_amt, c.income,
       cu.id AS cust_id, cu.company, cu.ext_data,
       COALESCE(a.acc_amt,0) acc_amt, COALESCE(a.tax_amt,0) tax_amt,
       a.first_acc_date
FROM contracts c
JOIN customers cu ON cu.id = c.cust_id
LEFT JOIN (
  SELECT contract_id, SUM(acceptance_amount) acc_amt,
         SUM(tax_amount) tax_amt, MIN(acceptance_date) first_acc_date
  FROM contract_acceptances GROUP BY contract_id
) a ON a.contract_id = c.id
WHERE c.status NOT IN ('作废') AND a.first_acc_date IS NOT NULL
```

`snapshot_quarter(snapshot_date_str)` 函数：
1. 执行上述 SQL
2. 计算 receivable / contract_asset / aging_bucket / auto_risk
3. 从 cust.ext_data 解析 customer_nature（复用 `custom_fields.parse_ext`）
4. `INSERT ... ON DUPLICATE KEY UPDATE` 写入 receivable_snapshots
5. 返回写入条数

## 边界与异常

- 合同无验收记录 → 不纳入报表（应收为负即预付，不属于两金口径）
- 多次验收 → ar_date 取首次，账龄按 snapshot_date − 首次验收日 计算
- cust.ext_data.customer_nature 为空 → 归入"其它事业单位"，前端标黄提示
- 跨季度修改人工填报 → 按 quarter+contract_id 唯一，互不污染
- 快照重复生成 → UNIQUE 约束 + ON DUPLICATE KEY UPDATE，幂等
